# Metaplate 0.5.0 Black-Box Audit for 0.6.0

**Audit date:** 2026-08-24  
**Package under test:** exact npm artifact `metaplate@0.5.0`  
**Overall verdict:** Healthy renderer and package; verifier hardening required for 0.6.0.

## Executive Summary

The published 0.5.0 artifact installs, imports, typechecks, renders, and builds correctly across the supported consumer shapes tested. No package-integrity, provenance, optional-peer, concurrency, native-renderer, custom-encoder, Fetch-response, or actual Next application blocker was found.

The main 0.6.0 work is a coherent verifier defect: 0.5.0 reliably rejects truncation, but accepts several specification-invalid headers and container topologies that are inside its documented structural scope. These are false-positive build checks, not arbitrary-code execution or denial-of-service findings. No hang, crash, or unbounded loop was found.

## Tested Matrix

- Published tarball: 28 expected files, verified npm registry signatures, verified provenance attestation.
- Runtime imports and optional-peer diagnostics: Node 20.20.2, 22.19.0, and 24.19.0.
- Published declarations: strict TypeScript 5.9 consumer with `types: []`, no React types, and no Node types for standalone entrypoints.
- Real integrations: Satori 0.33.4, Resvg 2.6.2, Sharp 0.35.3, React 19.2.8, Next 16.3.2, and Fontsource Inter 5.3.0.
- Rendering: SVG, PNG, JPEG, Fetch response, handler, wrong-encoder rejection, and eight concurrent renders.
- Framework: actual Next 16.3.2 static export using the documented adapter pattern; generated PNG visually inspected and structurally verified at 1200×630.
- Adversarial images: 316 truncation samples across five real fixtures plus generated PNG/JPEG/WebP header and topology violations.
- Repository release gate: lint, source types, example types, 175 tests, build, and dry-run package all pass.

## Required Before 0.6.0

### 1. Complete PNG structural validation — High

Reject:

- unsupported bit-depth/color-type combinations;
- nonzero compression or filter method and interlace values other than 0/1;
- zlib CINFO windows above 32 KiB;
- duplicate IHDR;
- indexed images with missing or late PLTE;
- unknown critical chunks.

The [PNG Third Edition specification](https://www.w3.org/TR/png-3/) classifies these as header or critical-chunk syntax, not compressed-payload decoding.

### 2. Complete WebP extended-container validation — Medium

Reject:

- canvas area above `2^32 - 1`;
- animation flag without mandatory `ANIM` control;
- animation frames that extend outside the declared canvas;
- nonzero odd-chunk RIFF padding.

These constraints are normative in [RFC 9649](https://datatracker.ietf.org/doc/html/rfc9649).

### 3. Reject zero-width JPEG frames — Medium

`imageDimensions` currently returns `{ width: 0 }` for a synthetic SOF/SOS/EOI sequence, and `verifyImage` can accept it with the same invalid expected width. Preserve the reproduction and reject a zero samples-per-line frame at the SOF boundary. The normative format is [ITU-T T.81 / ISO/IEC 10918-1](https://www.itu.int/rec/T-REC-T.81).

### 4. Promote black-box integration coverage — Medium

Convert the focused reproductions into normal regression tests and add one current-peer Next build smoke. Unit mocks did not reveal the plain-Node `next/og` resolution caveat; the real Next build did prove the supported workflow still works.

## Recommended Small Features

1. Add `lang?: string` to `PackageFont` and `LoadedFont`, and preserve it through `loadPackageFonts`. Satori and Metaplate's own `SatoriFont` mirror already support it.
2. Make `metaplate --help` and `metaplate --version` successful discovery commands.
3. Add safe SVG dimension/structure verification so output from `createSvgOg` can use the same build check as raster output. `detectFormat` already recognizes SVG, but `verifyImage` and the CLI do not.

## Deliberately Deferred

- AVIF verification: supported by the unknown-output escape hatch and by some crawlers, but cross-social compatibility and ISO-BMFF parsing make it larger than this hardening release.
- Built-in file/batch writer: current `render` + `writeFile` + `Promise.all` composition is clear, while a writer would introduce overwrite and filesystem policy.
- Node response `status`/`statusText`: useful symmetry with Next, but image success responses are normally 200 and route wrappers can own failures.
- Direct plain-Node execution of `metaplate/next`: Node ESM cannot resolve Next 16.3.2's extensionless `next/og`, but the actual supported Next build succeeds. Document the boundary and keep a real framework smoke before changing the specifier.

## 0.6.0 Exit Criteria

- Every invalid container in Spike 002 is rejected with a format-specific error.
- All real fixtures and legal edge cases remain accepted.
- The truncation sweep stays at zero false accepts and completes without a material performance regression.
- The published-package Node/type/provenance probe passes.
- The full real-peer render probe and Next static build pass.
- The repository `npm run check` gate is green.
