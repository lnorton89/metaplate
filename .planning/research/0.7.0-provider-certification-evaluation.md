# 0.7.0 provider certification and fixture isolation evaluation

**Date:** 2026-08-25
**Branch:** `feat/0.7-deployment-supply-chain`

## Provider certification

The repository has no provider credentials, deployment tokens, or deterministic
hosted runners available in this environment. The existing packed verifier
therefore certifies only provider-shaped local contracts:

- Vercel-style Web `Request`/`Response` Node function contract;
- Netlify-style `(request, context)` contract with `context.params`;
- generic long-lived Node HTTP service contract.

These remain `certified-local-contract` in `deployment-evidence.json`. None is
marked `certified`, because local emulation does not prove a hosted provider
build, deployment, routing configuration, or served artifact.

A real provider certification requires a reproducible provider build/deploy run,
captured output, image byte/dimension verification, metadata verification,
provider/runtime versions, commit SHA, and an artifact or evidence URL. The
existing deployment validator rejects a `certified` route without those fields.

## Framework fixture isolation

The current root graph contains Astro, Next, React Router, Express, Vite, native
renderer packages, and test/build tooling. The lockfile inventory classifies
these as `development-only`, `optional-platform`, or `runtime-peer`; none is a
regular published runtime dependency. The exact packed verifier installs the
Metaplate tarball and exercises framework fixtures against that artifact.

Moving the fixtures into independent manifests would reduce the root lockfile's
Socket deep-score surface, but it is not a safe mechanical change in this pass:
the current verifier shares the root lockfile's pinned peer/tool versions and
would need a dedicated deterministic install/cache workflow for each fixture.
The captured Socket baseline contains one high maintenance upgrade alert on a
runtime-peer transitive package and no critical alerts. The alert is explicitly
dispositioned; the remaining deep score is dominated by native/platform,
framework, optional-peer, license, and adoption signals rather than a confirmed
fixture-only vulnerability. Fixture isolation remains an evidence-based
maintenance option, but is not claimed as remediation without a measured
before/after report.

## Deferred runtime tracks

SvelteKit, Next 15, Astro SSR, Bun, and Deno remain un-certified. Their current
status is documented rather than inferred from Web API compatibility. Remote URL
verification, page metadata serialization, aspect-ratio layout variants,
streaming, and edge/Wasm rendering remain separate security/design tracks.
