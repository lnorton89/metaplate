# 0.6.0 research implementation status

**Updated:** 2026-08-24  
**Inputs:**
[social-network metadata research](./0.6.0_social-network-metadata.md) and
[framework integration research](./0.6.0_framework-integration-and-test-infrastructure.md)

This file records how the research was folded into the 0.6.0 release. It is a
scope and evidence map, not a substitute for the changelog or release notes.

## Implemented for 0.6.0

| Research requirement | Implementation and evidence |
| --- | --- |
| Independent Open Graph and X images | `socialImageMetadata` accepts ordered `openGraph.images` and one X-specific `twitter.image`, while the existing shared-image call remains unchanged. Inputs are copied into independent descriptors so later source mutation cannot desynchronize channels. |
| Configurable X Cards and identity | `summary`, `summary_large_image`, `site`, `siteId`, `creator`, and `creatorId` are typed and tested. |
| Honest platform guardrails | `socialImageCompatibility` provides universal, Open Graph, Facebook, X, LinkedIn, Slack, Mastodon, Discord, and Instagram profiles with `error`, `warning`, and `unknown` issues. Universal delivery requires absolute credential-free HTTPS and PNG/JPEG. |
| SVG delivery warning | Universal, Facebook, and LinkedIn profiles reject SVG and other undocumented raster formats; generic Open Graph/Slack/Mastodon profiles warn. README guidance distinguishes renderer output from crawler-safe delivery. |
| Resvg dimension invariant | Dimension-changing `fitTo` and all `crop` settings fail at plate creation. Actual native raster dimensions are asserted before pixels are returned or encoded. |
| Dynamic framework copy | Node and Next plates expose `handlerFrom`, forwarding every framework argument to a sync or async resolver without swallowing errors. Promised Next params and multi-argument Fetch handlers are tested. |
| Artifact-level framework tests | The exact tarball is built and exercised through Next 16 static export, Astro 7 static endpoint/page generation, Express 5 over HTTP, and React Router 7 generated route types plus a served dynamic resource route. |
| Runtime/safety documentation | The README now separates framework APIs from deployment runtimes, links each integration to its exact official framework contract, and documents bounded copy, caching, concurrency/timeouts, and remote-asset allowlisting. PR and release templates require those upstream references for future framework changes. |
| React-independent authoring shape | Plain-object authoring imports no React API and the public framework-neutral declarations require no React or Node types. React is nevertheless a required peer so the one-command install is immediately JSX-capable. Package verification tests both guarantees against the tarball. |
| One-command renderer install | Satori, Resvg, and React are required, bounded peers, so npm installs the complete renderer stack with `metaplate` and deduplicates compatible application copies. Next remains optional and application-supplied. |
| Bounded peer claims | Next, Satori, Resvg, and React peer ranges stop at their next breaking boundary. Next support is narrowed to the audit-clean, release-tested 16.3.2–16.x line. |

## Deliberately not claimed in 0.6.0

| Candidate | Decision |
| --- | --- |
| SvelteKit certification | Keep the typed Node-adapter recipe, but do not label it certified while the latest stable Kit dependency graph retains an upstream Cookie advisory. A forced override breaks Kit's published Cookie types. |
| Next 15 certification | Do not claim it. The latest Next 15 patch still fails this repository's high-severity dependency audit through PostCSS and Sharp. |
| Remote `verify-url` crawler | Defer until it has a dedicated threat model and implementation for DNS/IP validation on every redirect, private/link-local rejection, scheme/port controls, byte/time/redirect limits, and credential isolation. The local profile API makes no network-safety claims. |
| Page-level metadata and HTML serializer | Follow-on API. Image channel semantics should settle before Metaplate expands into a framework-neutral SEO object model. |
| Schema.org, Adaptive Cards, Slack app unfurls, and Discord bot embeds | Out of core scope; these are structured-data or application message contracts rather than social image descriptors. |
| Automatic square/landscape rendering | Follow-on renderer work. Text-heavy cards require layout-aware variants, not silent center crops. |
| X player/app cards and Open Graph video/audio | Follow-on feature with separate hosting, security, and required-field contracts. |

## Release gate

Before 0.6.0 is tagged, `npm run check`, `npm run check:package`, and
`npm audit --audit-level=high` must pass from a clean install. The checked-in
0.6.0 release notes must also pass `npm run check:release-notes`.
