# 0.7.0 deferred-item implementation status

**Updated:** 2026-08-25  
**Target release:** 0.7.0  
**Related:** [0.6.0 implementation status](./0.6.0-implementation-status.md), [deployment research](./0.7.0-deployment-routes.md), [Socket remediation research](./0.7.0-socket-dependency-remediation.md)

This document is the current disposition of deferred work. A deferred item is
closed only when code, documentation, and verification evidence exist. A
provider recipe is not called certified merely because its runtime resembles a
local Node process.

## Still blocked or intentionally separate

| Item | Reason and next action |
| --- | --- |
| Exact Socket score and alert remediation | Baseline captured in `socket-score-report.json`: one high maintenance upgrade opportunity and no critical alerts. The high alert is explicitly dispositioned in `socket-dispositions.json`; re-query before release because Socket scores and package availability change over time. |
| SvelteKit certification | The release-tested latest stable dependency graph has an upstream Cookie advisory. Revisit when the adapter's dependency graph is fixed or an isolated fixture can be audited cleanly. |
| Next 15 certification | The declared support line remains Next 16.3.2–16.x because the audited Next 15 graph still fails the repository's high-severity audit policy. |
| Next dynamic-server and Astro SSR certification | Requires adding the corresponding server adapters and maintaining fixture-specific production runners. The current release now has provider-shaped Web Standard and generic Node local contract coverage, but still does not claim hosted Next dynamic-server or Astro SSR certification. |
| Remote `verify-url` | Requires a security-reviewed fetcher with redirect DNS/IP re-resolution, private/link-local rejection, scheme/port controls, byte/time limits, and credential isolation. It is not safe to add as a thin `fetch(url)` command. |
| Page-level metadata/HTML serializer | Remains a separate API design because framework metadata unions, tag ordering, canonical URLs, and escaping need a stable contract and dedicated tests. |
| Square/landscape plate variants | Requires layout-aware reflow rather than automatic cropping. Keep as renderer design work. |
| Edge/Wasm renderer | Requires a real renderer, font, asset, and output-compatibility fixture. The native Node API is not silently changed. |
| X player/app cards, OGP video/audio, Schema.org, Adaptive Cards, app unfurls | Separate contracts with different required fields and hosting/security semantics. |
| Bun/Deno certification | Requires dedicated runtime matrices; Web API compatibility alone is insufficient evidence. |
| Streaming output | Requires measured encoder/provider behavior and changes the current buffered-response contract. |

## Release rule

The 0.7.0 release may claim documented recipes for the routes listed in
`deployment-evidence.json`, but only a route with complete artifact, build,
output, image, and metadata evidence may be marked `certified`. Socket status
must remain `awaiting-alert-export` until the individual alerts are available;
`npm audit` passing does not change that status.
